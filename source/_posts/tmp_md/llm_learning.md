>
> 记录方式：每一站都写清 **① 我为什么会问 → ② 解决了什么疑惑 → ③ 它在大模型学习地图上的位置**。数学用纯文本（Cursor 不渲染 LaTeX）。

## 〇、先立一张地图：大模型是怎么把文字变成下一个词的

理解我全部提问的关键，是先有这张"数据流水线"图。一句话进模型、一个字出来，中间要走这么一条流水线：

```
文字
  │  ①分词 Tokenize（查字典，按频率切）
  ▼
token id（整数编号，无语义）
  │  ②查 Embedding 表（训练学出来的）
  ▼
词向量（896个数的"语义指纹"）
  │  ③进入 N 层堆叠（这里是24层），每层 = Attention + FFN
  │     Attention：词之间互相看，理解上下文、消歧、指代
  │     FFN      ：每个词单独深加工，主要存事实知识
  ▼
最后一层输出 logits（每个候选词的"原始分数"，共151936个）
  │  ④Softmax（把分数变成合法概率）
  │  ⑤temperature / top-k / top-p（重塑分布 + 挑候选）
  ▼
采样出下一个词 → 接回输入，循环 ①~⑤
```

**我的追问主线，恰好是沿着这条流水线从右往左、从表到里走的**（这也是学任何系统最自然的路径——先摸你天天在碰的旋钮，再顺藤摸瓜往里挖）：

```
起点：⑤采样/temperature（最右端，最贴近"使用"，我平时就在调它）
  ↓ 往左挖
   ④softmax → logits（分数怎么变概率、分数是什么）
  ↓ 一个大转弯：那 logits 到底怎么算出来的？
   ③Attention（模型的核心，怎么理解上下文）
  ↓ 继续往左
   ②Embedding、①分词（词怎么变成有语义的数字）
  ↓ 再往深（贯穿整条线）
   参数 / 知识存储（这些数字里到底装了什么，凭什么会"懂")
```

下面三幕，就是我沿着这条线一路问下去的完整过程。

# 第一幕：从"调 temperature"到"看懂输出端"

> 地图位置：流水线最右侧的 ④⑤（softmax + 采样）。
> 这一幕解决的大问题：**模型算出结果后，是怎么"选"出下一个词的？**

我平时用大模型 API 时会调 `temperature`，知道"调大更随机、调小更稳"，但完全是黑盒。这一幕就是想把这个黑盒彻底打开——结果一路问下去，把它背后的 softmax、logits 全牵出来了。

## 1.1 我问："temperature 到底怎么筛选结果？"

**为什么问**：我以为 temperature 和 top-k/top-p 一样，是"筛掉一些词"。

**解决的疑惑**：这是个误解。**temperature 不删任何词**，它只在 softmax 之前把每个 logits 除以 T，改变整个分布的"陡峭程度"：

```
T < 1：分数差被放大 → 分布更尖 → 高分词更霸道（保守）
T = 1：原样
T > 1：分数差被压缩 → 分布更平 → 低分词也有机会（发散）
```

**实验佐证**（同一份 logits 各抽 1000 次）：T=0.2 时第一名"公园"命中 1000/1000；T=1.0 命中 378 次；T=3.0 命中 0 次、99.7% 落到冷门词（因为词表15万，压平后概率被摊到长尾——这正是**温度太高会胡说**的根源）。

**地图位置**：第 ⑤ 步。第一次意识到"选词"是可调的，且 temperature 属于"重塑分布"而非"删词"。

## 1.2 我问："temperature 取值范围？logits 是啥？logits/T 怎么算？"

**为什么问**：上一个问题让我发现自己**基础概念是空的**——连 logits 是什么、除法具体怎么发生都不清楚，没法再往下。

**解决的疑惑**：

- **logits**：模型最后一层对每个候选词输出的**原始分数**，可正可负、无界、不是概率、只有相对大小有意义。
- **T 取值**：必须 > 0；T→0 等于贪心，0~1 保守，1 原样，>1 发散；工程常用 0~2。
- **logits/T**：就是每个分数都除以同一个 T。真实例子：公园 15.462、爬 13.966，T=0.5 时差距放大→公园 90.8%；T=2.0 时差距压缩→公园 44.8%。**除以 T 不改变谁大谁小，只改变差距。**

**地图位置**：仍在 ⑤，但补齐了 logits（④的产物）这个关键名词，为往左走铺路。

## 1.3 我问："为什么要有这一步？为什么输出要经过 temperature？"（并追问"你这是望文生义，没说到本质"）

**为什么问**：知道了"怎么做"，但不知道"为什么要做"。而且我对第一版"为了在稳定和多样间切换"的回答不满意——那是**现象**不是**本质**，我要更深的。

**解决的疑惑**（这是第一幕的高潮，挖到了两层本质）：

**本质一（数学）**：softmax(logits/T) 精确等价于把原概率分布做幂次重整：

```
p_i(T) = p_i^(1/T) / Σ p_j^(1/T)
推导：exp(z/T) = (exp z)^(1/T)，常数在归一化时消掉
端点：T→0 得 p^∞=只留最大项(贪心)；T=1 得 p 本身；T→∞ 得 p^0=均匀分布
```

所以 temperature 是"在 **分布众数 ↔ 分布本身 ↔ 均匀分布** 之间连续滑动"的旋钮。

**本质二（为什么需要它）**：模型用最大似然训练，目标是当**好的预测器**——好预测器绝不敢给任何词判 0 概率，会留很厚的长尾来对冲意外。但"好预测器"≠"好生成器"。模型只会输出"预测最优"的分布(T=1)，它不等于"生成最优"。**temperature 就是弥合"预测最优 ≠ 生成最优"这个内在错位的最简单旋钮。**

**地图位置**：④⑤ 交界处的"为什么"。这一问把 temperature 从"一个旋钮"升级成"理解模型训练目标与生成目标之间张力"的入口。

## 1.4 我问："没有其他类似的方式了吗？"

**为什么问**：既然 temperature 是为了控制输出，那控制输出应该不止这一招。

**解决的疑惑**：控制解码是一个大家族，按机制分四类：

- **A 重塑分布（和 temperature 同族，不删词）**：temperature、重复惩罚、presence/frequency penalty
- **B 截断候选（删词）**：top-k、top-p、min-p、typical
- **C 怎么选**：贪心、随机采样、beam search、contrastive search
- **D 硬约束**：logit bias、禁用词、语法/JSON 约束解码
- 还有自适应的 Mirostat 等

**地图位置**：把 ⑤ 从"一个旋钮"扩展成"一整块控制面板"，知道了 temperature 在其中的坐标。

## 1.5 我问："T≤1 感觉都是贪心啊？"

**为什么问**：前面看到 T=0.2 时"公园"几乎必中，我误以为只要 T≤1 就退化成贪心了。

**解决的疑惑**：用数据推翻（判据：贪心=第一名命中率100%、只有1个词）。

```
有把握的位置("的首"→座): T=1.0 命中34%, 出现48个不同词
没把握的位置("颜色是"→蓝): T=1.0 命中20%, 出现243个不同词
```

**像不像贪心 = f(T, 分布陡峭度) 的乘积**：只有 T→0 才保证贪心；中间的 T 像不像，取决于模型对当前词有没有把握。**T 不是"贪心开关"，是"把模型已有的自信程度再放大或缩小"的乘数。**

**地图位置**：深化 ⑤，纠正了"T 单独决定确定性"的错觉——它和模型输出的分布形状是**相乘**关系。

## 1.6 我问："感觉 temperature 是配合 softmax 一起用的？"

**为什么问**：反复接触后，我隐约觉得 temperature 和 softmax 分不开。

**解决的疑惑**：**直觉完全正确**。temperature 不是独立步骤，它就是"带温度的 softmax"里的一个参数（普通 softmax = T=1）。而且它**能起作用完全靠 softmax 里的 exp**：

```
用 softmax(有exp)：改 T 有效果
用线性归一化 z/Σz(无exp)：三个不同 T 结果完全一样（T被约分消掉）
原因：exp 把"除以T"变成"取1/T次幂"，幂不会被归一化约掉
```

**地图位置**：把 ⑤(temperature) 正式并入 ④(softmax)——它们本是一回事。这一问成了从"采样"走向"softmax"的桥。

## 1.7 我问："没理解 softmax 的作用？为什么要做这个操作？"

**为什么问**：既然 temperature 依附于 softmax，那 softmax 本身我也没真懂，得回头补。

**解决的疑惑**：

- **作用**：logits 有两个毛病（可能为负、加起来不为1），没法当概率。softmax 把"任意实数向量"变成"非负、和为1"的合法概率（供解释、采样、算loss）。
- **为什么用 exp**：①强制变正数；②保持排序；③只看差不看绝对值（p_i/p_j = e^(z_i−z_j)，全体加常数分布不变）。
- **最深一层**：logits 其实是"对数概率"。模型在**对数空间**里算（因为一整句概率是连乘，小数连乘会下溢，对数空间变连加更稳；且线性层天然输出无界实数，正对应对数概率）。softmax 的 exp 就是把它还原回概率空间。

**地图位置**：正式拿下 ④。至此输出端(④⑤)全通，并且"logits 是对数概率"这个认知，为"往左挖 logits 从哪来"埋下伏笔。

## 1.8 插曲一（数学）：e^(2/3) 到底等于什么

**为什么问**：1.3/1.6 反复用到 exp(z/T)=(exp z)^(1/T)，我把 `e^(2/3)` 误当成了 `e²/e³`。

**解决的疑惑**：三条法则别混：

```
幂相乘,指数相加: e^a·e^b = e^(a+b)
幂相除,指数相减: e^a/e^b = e^(a-b)   ← 我误以为的
幂的幂,指数相乘: (e^a)^b = e^(a×b)   ← 实际用的
```

`e^(2/3)` 中 2/3 是"2×1/3"一个数(≈0.667)，不是"e² 除以 e³"。

**地图位置**：不在流水线上，是支撑 1.3/1.6 推导的数学地基。

## 1.9 插曲二（工程）：现在的 Agent 会动态调 temperature 吗？Opus 泄漏了吗？

**为什么问**：懂了 temperature 的原理，自然好奇真实产品（Cursor/Claude）里它是怎么用的、是不是每轮动态调。

**解决的疑惑**（联网核查）：

- temperature 是**解码阶段的外部参数**，模型自己不会调；默认一次请求内固定。
- 所谓"Opus 泄漏"指的是 GitHub 上的**系统提示词**，那是提示词文字、**不含 temperature**，也不是实现。
- **关键事实**：从 Claude Opus 4.7 起，temperature/top_p/top_k 被**废弃**，API 设非默认值直接 400 报错（4.8、5 同）。替代旋钮是 `effort`（控制推理深度，不是采样温度）。
- 结论：我"agent 会调"的直觉——**在 effort 维度上对，在 temperature 上反而被取消了**。方向对，参数认错。

**地图位置**：⑤ 的工程现实。让原理和真实产品对上账。

### 第一幕小结

我从一个 API 旋钮出发，问到了 temperature 的机制→本质→与 softmax 的关系→softmax 本身，**把流水线右半段（④softmax + ⑤采样）彻底打通**。而"logits 是对数概率、是模型算出来的"这个尾巴，直接把我推向了第二幕。

# 第二幕：一个大转弯——"那 logits 到底是怎么算出来的？"

> 地图位置：流水线中段 ③（N 层 Attention + FFN），模型的核心。
> 这一幕解决的大问题：**模型凭什么能"理解"一句话，从而算出靠谱的 logits？**

第一幕结尾我知道了 logits 是模型内部算出来的原始分数。自然的下一问就是：**内部到底怎么算的？** 这就撞上了 Transformer 的心脏——Attention。（对应脚本 `04_attention.py`）

## 2.1 我问："为什么有 attention 这一步？是为了确定'他'还是'她'吗？"

**为什么问**：想知道 attention 存在的意义，我拿"代词指代"当切入点猜。

**解决的疑惑**：语言里词的意思高度依赖上下文，attention 就是让每个词**按需回看上下文、确定自己真正含义**的机制。指代只是冰山一角，还有：

- 一词多义："买**苹果**"(水果) vs "**苹果**发布手机"(公司)
- 远距离搭配："我**不**觉得这个方案**好**"（"好"要关注远处的"不"）

关键是"**动态、按需**"：每个词看谁、看多重，是模型根据内容当场算的，不是写死的。

**地图位置**：正式进入 ③。理解了"为什么需要这一层"。

## 2.2 我说"继续"，于是问：模型具体怎么算出"该看谁"？（Q/K/V）

**为什么问**：知道了 attention 干嘛，但"该看谁"这个判断到底怎么做出来的，还是黑盒。

**解决的疑惑**：同一个词乘上三个可学习矩阵，分裂成三个身份：

| 角色 | 含义 | "他" | "小明" |
|---|---|---|---|
| Query 查询 | 我在找什么 | "我是代词，找我指的人" | — |
| Key 键 | 我是什么标签 | — | "我是人名、主语" |
| Value 值 | 我的内容 | — | "小明的信息" |

流程：**我的 Q 去和每个词的 K 算匹配分（点积）→ softmax 成权重 → 按权重把各词的 V 加权融合**。于是"他"的新表示里灌进了 70% 的"小明"信息。

**地图位置**：③ 的核心机制。这是整个学习里最硬的一块。

## 2.3 插曲："我看不懂"——退回直觉重讲

**为什么发生**：2.2 一上来堆了矩阵和热力图，我跟不上。

**解决方式**：抛开公式，用"图书馆查资料"的比喻重讲——Q=你的问题，K=每本书的书名，V=书的内容；拿问题对书名找相关的，再按相关度把内容揉在一起。**这次通了。**

**这条经验值得记**：新概念先建直觉，再上数学；顺序反了就"看不懂"。

## 2.4 我问："向量的点积对应余弦定理吧？"

**为什么问**：2.2 说"Q·K 算匹配分"，我联想到点积和几何里的余弦有关。

**解决的疑惑**：对，而且余弦定理正是点积公式的来源：

```
a·b = |a||b|cos(θ)              ← 就是余弦定理的向量形式
余弦相似度 = cos(θ) = a·b/(|a||b|)  ← 除掉长度只看方向
```

attention 里的 Q·K 是**裸点积**（含方向+长度），所以要"÷√d 缩放"防止维度大时数值过大把 softmax 挤饱和。

**地图位置**：③ 内部的数学地基。把"匹配分"落到了几何直觉上。

## 2.5 我问："生成每个新词，都要和前面每个词遍历一遍吗？attention 是用来纠正的吗？"

**为什么问**：想搞清 attention 在"逐字生成"时的实际运作和真正职责。

**解决的疑惑**：

- **是的，要遍历**：新词产出自己的 Q，和前面每个词的 K 逐个算分、再融合它们的 V；且每层每头都做一遍。
- **关键优化 KV 缓存**：前面词的 K/V 早算过并**缓存**，新词直接取用，不重算。推论：输入越长缓存越大，这是长上下文吃内存的根源。
- **不是纠正**：attention 的职责是**融合上下文、消歧、聚合信息**，不判断对错、不改已有的词。比喻：不是"改作业的老师"，是"做决定前先环顾四周收集情报"。

**地图位置**：③ 的运行时视角（生成循环 + KV 缓存），并厘清了它的职责边界。

### 第二幕小结

沿着"logits 从哪来"，我钻进了模型核心 ③，搞懂了 **attention 怎么让词理解上下文**（Q/K/V→匹配→融合），也知道了它在生成时靠 KV 缓存高效运作。但新问题又冒出来：Q/K/V 是从"词向量"算的，那**词向量又是怎么来的？里面凭什么有语义？** 于是继续往左，进入第三幕。

# 第三幕：再往左、再往深——"词怎么变成有语义的数字？知识到底存哪？"

> 地图位置：流水线最左的 ①②（分词、embedding），以及**贯穿整条线的"参数"**。
> 这一幕解决的大问题：**模型这一堆数字，凭什么会"懂"知识和技能？**

## 3.1 我问："意思相近的词，指纹也接近？是不是它们的 token 差不多？词转 token 有规则吗？"

**为什么问**：第二幕说"词向量（指纹）意思近就接近"，我把"指纹"和"token"搞混了，以为语义在分词那步就有了。

**解决的疑惑**：这是个关键澄清——**"指纹"和"token"是两回事**，词转数字其实分两步：

```
词 ──①分词(查字典,按频率)──▶ token id(整数编号,无语义) ──②查embedding表(训练学的)──▶ 指纹向量(有语义)
```

**数据验证**：token id 上"汽车(100343)"比"狗(100737)"更接近"猫(100472)"，但意思无关；而 embedding 相似度严格跟着语义走（开心↔高兴 0.54 > 猫↔狗 0.42 > 猫↔开心 0.06）。

**结论**：语义**不在分词那步**（那只是按频率查字典拿编号），而在"token 查 embedding 表"这一步，且 embedding 是**训练学出来的**。

**地图位置**：拿下 ①②。终于明白语义是从哪"注入"的。

## 3.2 我问："每层 14 个头是什么意思？"

**为什么问**：知道模型有 24 层，但"每层 14 个头"没概念。

**解决的疑惑**：一个头 = 一整套 Q/K/V 注意力。**14 个头 = 同一层里并行做 14 套注意力，每套从不同角度看这句话**（指代/语法/情感…）。因为一套注意力每个词只能给出一种"该看谁"的分配，顾此失彼；多头让它能同时兼顾多种关系。切分方式：896 维 ÷ 14 头 = 每头 64 维，各算各的再拼回 896。（induction heads 这类专门头是上下文学习能力的机制基础。）

**地图位置**：③ 的横向结构（多头）。

## 3.3 我问："FFN 是每次推理生成的吗？14 从哪来？896 维是什么意思？"

**为什么问**：开始关心模型的"骨架"——这些结构数字是怎么回事、FFN 是不是动态产生的。

**解决的疑惑**：

- **FFN 不是每次生成的**：它是每层里一个小神经网络，参数训练时学好、之后**冻结**；推理时用同一套固定矩阵加工每个词。比喻：出厂调好的榨汁机，放不同水果出不同汁，机器本身不重造。知识固化在它的构造里。24 层各有独立的一台。
- **14 是预设的**：训练前由结构写死。
- **896 维**：每个词的指纹就是**一串 896 个数字**（'猫'的向量形状 (896,)）。单个数字无意义，896 个合起来把词定位在 896 维空间的一个点。

**地图位置**：③ 的纵向结构（层内 FFN + 固定参数），并引出"参数"这个贯穿全线的主题。

## 3.4 我问："为什么是 896 维？不能是 1 万维吗？0.5B 是什么意思？有关联吗？"

**为什么问**：想搞清这些结构数字之间是不是有内在联系，为什么偏偏这么定。

**解决的疑惑**：它们是**同一件事的因果两端**：

- **0.5B** = 5 亿个**参数**（所有可学习数字的总数）。真实值 494M，其中词嵌入表占 28%。
- **维度决定参数量**：每层参数主要正比于 hidden²。所以 896 维（配 24 层等）一乘，就得到约 0.5B。
- **能不能 1 万维？** 能，但参数 ∝ hidden²，896→10000（涨11倍）参数涨约125倍 → 变成 47B 的巨无霸，不再是 0.5B，这台无 GPU 的机器也跑不动。

因果链：`目标规模(0.5B) → 反推 → 定维度896/层24/头14/FFN4864 → 一乘 → 参数≈0.5B → 决定能装多少知识、多少显存、多快`。

**地图位置**：把 ③ 的所有结构数字（维度/层/头/参数）串成一条因果链。

## 3.5 我问："'越能装知识'到底怎么理解？"

**为什么问**：常听说"参数越多越能装知识"，但"装知识"是个模糊的说法，我要具象。

**解决的疑惑**：

- 知识分两类，都存在参数（矩阵里的数字）里：**事实性知识** + **技能/规律**。训练把随机数字调成"能正确预测下一个词"，知识就固化在取值里。
- **是分布式存储**：一条事实分散在成千上万参数里，一个参数又参与无数知识。像一幅画不是"一像素一物体"，像素总数（参数量）决定能画多清晰。
- **容量有限的实验**：0.5B 模型答"中国首都""水分子式"全对；但问"1998诺贝尔物理奖"就**全编造**（列了投资家、DNA生物学家、已故的费曼）。冷门知识挤不进有限容量，模型又不会说"不知道"，就用最像的模式硬凑——这就是**幻觉**的一个来源。

**地图位置**：贯穿全线的"参数"主题，理解了参数量 = 知识容量上限。

## 3.6 我问："事实性知识存在 FFN 里？技能/规律存在哪？"

**为什么问**：既然知识存在参数里，那不同类型的知识是不是存在模型的不同部位？

**解决的疑惑**（分"有证据"和"没定论"讲）：

```
事实性知识 → 主要(不是全部)集中在 FFN 层（有证据：FFN像键值记忆库；ROME能靠改FFN定点改一条事实）
技能/规律  → 更多靠 attention(关系/操作/induction heads) + 跨层协作，更分散
```

**重要提醒**：这不是干净的二分。知识和技能是**分布式、纠缠的**，仍是活跃研究领域，"事实=FFN、技能=attention"只是方便理解的简化。

**地图位置**：给 ③ 里的两个部件（Attention vs FFN）做了"职能划分"，但诚实标注了边界。

## 3.7 我问："attention 看着就是个方法（拿 Q 找 K、V），它凭什么会存'技能'？"

**为什么问**：这是全程最尖锐的一问——attention 明明是一套固定流程，怎么可能"学会"技能？

**解决的疑惑**（这是第三幕、也是整条主线的收口）：我漏了关键一步——**Q/K/V 不是现成的，是算出来的**：

```
Q = 词向量 × Wq    K = 词向量 × Wk    V = 词向量 × Wv
（真实数据：单层 attention 的 Wq/Wk/Wv/Wo 就有 183 万个可学习参数）
```

拆开看：

| 部分 | 固定/可学 | 是什么 |
|---|---|---|
| 流程 Q点K→softmax→加权V | **永远固定** | 死的运算步骤 |
| Wq/Wk/Wv 怎么把词变Q/K/V | **训练学出来** | **技能藏在这里** |

技能怎么进去：训练时见了无数"代词指代人名"的句子，把 Wq/Wk 调成"让代词的 Q 正好匹配人名的 K"。于是这条规律固化成了矩阵里几十万个数字的取值。**流程决定"怎么算"，Wq/Wk/Wv 决定"算什么"；技能不在流程，在旋钮。**

比喻：全世界 Transformer 的流程都一样（同一套搜索算法），GPT-4 比 0.5B 强，强在这些矩阵里的数字（排序权重）和数量。

**地图位置**：回到 ③ 的最本质处，也解开了贯穿全程的终极困惑——**"固定的方法" + "学出来的参数" = 会技能的模型**。

### 第三幕小结

从"词向量哪来"一路问到"知识/技能存哪、凭什么会懂"，我把流水线最左端（①②）和贯穿全线的"参数"主题都拿下了。最后 3.7 那一问，其实把整条主线收束成一句话：**大模型 = 固定的流水线流程 + 海量训练学出来的参数取值。**

# 补幕（次日）：再挖最左端 ①分词——Token 表从哪来、够不够用、为什么每个模型都不同

> 地图位置：流水线最左的 ①分词。第三幕 3.1 只分清了"分词≠语义"，这一幕接着往下追问分词本身：词表怎么来、有限的表怎么覆盖无穷的输入、跨模型通不通用。
> 这一幕解决的大问题：**Token 表到底是个什么东西，它和模型是什么关系？**

## 补.1 我问："每个词都有指纹向量吗？输入是无穷的、模型是有穷的，碰到表里没有的词怎么办？"

**为什么问**：3.1 说"token 查 embedding 表拿指纹"，我立刻想到一个漏洞——用户能打出无穷多的词，模型的表却是有限的，遇到没见过的词岂不是查不到、没法给指纹？

**解决的疑惑**：关键转折——**模型存的不是"词"的指纹，是"token（片段）"的指纹**。词表固定有限（Qwen2.5 = 151,643 个 token），但任何输入都会被切成表里已有的片段，切到最碎就是字节，所以永远不会"查不到"。

**真实验证**（本机 Qwen2.5 分词器实拆）：

```
苹果   -> 1个token（常见词，整词独占）
曹操   -> 1个token（常见人名，整词独占）
GPT    -> 2个token: G + PT
antidisestablishmentarianism -> 6个token: ant+idis+establish+ment+arian+ism（长词拆词根）
阿斯顿嘎嘎嘎(瞎编) -> 5个token: 阿+斯顿+嘎+嘎+嘎（拆碎）
囧 / 彁(生僻字)    -> 各拆成 2 个"字节"token（显示为 �）
```

**规律**：越常见越可能整词占一个 token，越生僻拆得越碎；终极兜底是词表里塞的 **256 个"字节"token**——任何字符最终都是字节，所以中文、生僻字、emoji、乱码全能拼出来，一个不漏。**推论**：生僻词被拆成一堆碎片，模型只能靠"碎片向量 + attention 现场拼"来理解，所以它对生僻词/生僻名/罕见拼写更容易出错。

**地图位置**：深化 ①。补上"有限词表如何覆盖无限输入"的机制（subword 子词 + byte 字节兜底）。

## 补.2 我问（上上个问题）："先有 token 再训练模型，还是先训练模型再生成 token？"

**为什么问**：既然词表是承载语义的东西，我想搞清 token 表和模型参数谁先谁后、谁生成谁。

**解决的疑惑**：**先有 token 表，再训模型。** 而且这里其实有两次**完全不同**的"训练"，容易混：

```
② 训练分词器（先做）：纯统计，用 BPE——"谁老挨在一起就合并成新token"，
                      反复合并直到凑够15万个。产出一张固定的表。快（几小时）。
④ 训练模型（后做）  ：梯度下降/反向传播，把已有token的向量+所有参数练准。慢、烧钱。
```

- token 表在训模型**之前就冻结**；训练只调向量取值，**不增删 token**。"生成token"发生在第②步，且不是模型生成的，是分词器用统计建出来的。
- **为什么必须先定死表**：模型开头的 embedding 表（15万 × 维度）和结尾的输出层（× 15万）尺寸都焊在词表大小上，中途改表 = 这两个表形状全变 = 之前练的全废。
- BPE 还回头解释了补.1 的现象：**高频组合被合并成整 token（苹果=1个），低频组合永远轮不到合并、只能停在碎片（阿斯顿嘎嘎嘎=5个）**。

**地图位置**：厘清 ① 与参数训练的先后与因果——分词器是"训模型之前就定死的私有字典"。

## 补.3 我问（上一个问题）："这样每个模型、甚至同模型不同版本，token 表都不一样？"

**为什么问**：既然表是各自训练前定的，那不同模型的表应该互不相同——想确认这个推论，以及它带来的后果。

**解决的疑惑**：**推论正确。**

- **不同家族不同表**：GPT-2(~5万) / GPT-4 cl100k(~10万) / GPT-4o o200k(~20万) / LLaMA2(3.2万) / LLaMA3(12.8万) / Qwen2.5(15.1万)。
- **大版本升级通常换表**（GPT-4→4o、LLaMA2→3、Qwen1→2）；**同代不同大小通常共用**（Qwen2.5 的 0.5B/7B/72B 同一张表）；**微调版沿用原表**（所以能在原模型上接着练）。
- **四个实际后果**：
  1. **token id 是模型内部编号，跨模型毫无意义**——id 5000 在 A、B 模型里指的东西毫不相干。
  2. **权重不能混用**——连"第几号 token 是什么"都对不上，A 的层塞进 B 全是乱码。
  3. **同一句话在不同模型里 token 数不同** → 花的钱、占的上下文都不同（API 按 token 收费）。
  4. **中文差异尤其大**——早期英文模型一个汉字常拆成 2-3 个字节 token，中文模型常见汉字/词多是 1 个 token → 中文任务更省 token、更顺。

**地图位置**：① 的边界属性——词表是每个模型的"私有字典"，不通用。这解释了为什么 token id 和权重都无法跨模型迁移。

### 补幕小结

3.1 分清了"分词只是查字典拿编号、语义在 embedding 那步"，这一幕把"字典"本身挖穿了：**它是训模型前用 BPE 统计合并出来的一张有限表（约15万片段），靠"子词+字节兜底"覆盖一切输入；它是每个模型训练前定死的私有产物，因此 token id 和权重都不跨模型通用。** 至此，流水线最左端 ① 也彻底通了。

# 补幕二（隔周）：把零件拼成整体——Transformer 架构 + 几个延伸澄清

> 地图位置：这一幕不新增流水线的段落，而是**把前三幕散落的零件（注意力、FFN、embedding、softmax、参数）拼成一张完整的架构图**，并补几个之前没记的延伸问题。
> 这一幕解决的大问题：**这些零件合起来，到底长成一个什么样的"整体"？为什么这样搭就能越来越懂？**
>
> 学习方式提醒（延续 2.3 的教训）：这一幕我一度又"一次堆太多零件"导致卡壳，最后是靠**一个比喻只讲一个点、讲不通就换比喻**才通的（工厂流水线 → 数字被推准 → 一层推一步推理）。记录时保留这些"最终讲通的那个说法"。

## 补二.1 我问："Transformer 架构是啥？"

**为什么问**：反复听到"GPT/Opus 都是 Transformer"，但从没有一张整体图。

**解决的疑惑**：Transformer 不是新东西，是**把已学零件按固定方式搭起来的蓝图**（出身：2017《Attention Is All You Need》）。最终讲通的比喻是**工厂流水线**：

```
一句话(所有字) → 分词+embedding
   ▼ 车间1：① 注意力(字们互相聊，收集上下文) → ② FFN(每个字自己消化)
   ▼ 车间2：同样两步（踩在车间1的结果上）
   ...
   ▼ 车间N：（Qwen0.5B=24层，大模型几十~上百层）
   ▼ 最后一层的向量 → lm_head → logits → softmax → 下一个字
```

- 一个"车间"= 一个 Transformer Block，内部固定是 **LayerNorm → 注意力 → 残差；LayerNorm → FFN → 残差**，正对应 model.py 的两行 `x = x + attn(ln_1(x))` / `x = x + mlp(ln_2(x))`。
- GPT/Opus/Qwen 都是 **decoder-only**（只堆这种带因果注意力的车间），nanoGPT 同款、只是小。
- 相比老的 RNN 的三个优势（都学过了）：**并行**（一层内所有字一起算）、**长距离**（任意两字直接用注意力挂钩）、**能堆很深**（靠残差+LayerNorm 稳住）。

**地图位置**：把流水线③段展开成"堆 N 个车间"，是整份总结的架构收口。

## 补二.2 我问："为什么走过越多车间，理解越深？"（连问了好几轮才通）

**为什么问**：这是本幕最卡的一问。我不接受"多几层就深一点"这种没机制的说法。

**解决的疑惑**（三个角度，最终靠后两个讲通）：

- **（数学角度，一度没懂）**：一层=一个函数 f，过 N 层=函数复合 `f_N(…f_1(x))`；残差让每层是"加一个修正量 Δ"→逐步逼近；**非线性是关键**——实验证明纯线性堆 N 层 `W2·(W1·x)=(W2·W1)·x` 等于 1 层（深度白给），中间加个非线性(relu/GELU)才让"两层>一层"，深度才有意义。
- **（"数字被推准"比喻，开始通了）**：把"苹果的意思"简化成 0~100 一个数（0=水果,100=手机），起点 50（不确定）。"吃了一个苹果"→50→32→20→12→6；"买了一台苹果"→50→64→82→94。**每过一层，旁边的字就把这个数往对的方向推一点；层越多，推的次数越多，越准。理解变深=代表意思的数被一步步推准。**
- **（"一层推一步推理"比喻，彻底通了）**：例子"小明的爸爸的妹妹的儿子"——必须一步步推：爸爸→A、A的妹妹=姑姑→B、B的儿子=表兄弟。**一个车间只能往前推一步，且每步都得踩上一步的结果。** 简单意思一两层够；要绕 5 步才懂的意思，只有 2 层就到不了终点 → 这就是"层不够、理解不深"。

**地图位置**：解释了流水线③"为什么要堆很多层"的根本原因——**理解是逐层累加、越踩越高的推理链**。

## 补二.3 我问："假设 16 层，就是把输入拆成 16 步一次执行吗？"

**为什么问**：想确认"层"到底怎么运行，怀疑是不是把输入切成 16 份。

**解决的疑惑**（纠了一个关键误区）：

- **不是拆输入**：是**整句话（所有字一起）**顺序走完 16 个车间；不是"小明进车间1、的进车间2"。层数(16)和字数是两回事。
- **一次前向只吐一个字**：整句顺着 16 层走一遍=一次前向=产出下一个字；然后新字接到句尾，**整句再走一遍 16 层**出下一个字（KV 缓存避免重算前面的字）。
- **层内并行、层间串行**：同一层里所有字同时算（快）；但车间2 必须等车间1 的结果（层这个方向必须串行）→ 层太多会让每次生成变慢。

**地图位置**：厘清③的运行方式（整句 × N 层顺序加工 → 出一字 → 循环）。

## 补二.4 我问："那每层具体怎么让理解更深一点？"

**为什么问**：知道"要很多层"，但单独一层到底加了什么，还没落地。

**解决的疑惑**：一层就干两件已学的事——**注意力(问旁边、收集上下文) + FFN(自己消化)**。加深的机制在于"踩肩膀"：

```
车间1：'妹妹' 问到前面的 '爸爸' → 更新成 '姑姑'
车间2：'儿子' 问到的 '妹妹'，已是车间1更新过的 '姑姑' → 更新成 '表兄弟'
```

**关键**：第2层里每个字问到的邻居，是"上一层已加工过、变聪明了"的邻居；再加残差 `x = x + 新信息`（不擦掉重写，而是把新懂的累加上去）→ 理解一层层攒起来。

**地图位置**：③ 内部单层的增量视角——注意力+FFN+残差 = 每层往上垒一点理解。

## 补二.5 我问："QKV、FFN、lm_head 三者什么关系？"

**为什么问**：这三个部件老搞混，想一次理清。

**解决的疑惑**：

| 部件 | 在哪 | 干嘛 | 输入→输出 |
|---|---|---|---|
| **注意力(QKV)** | 每层第①道 | 字与字交流、收集上下文（看别人） | 896→896 |
| **FFN** | 每层第②道 | 每个字结合知识独立深加工（看自己） | 896→896 |
| **lm_head** | 全程仅1个，最末尾 | 把最终向量翻译成每个候选词的分数(logits) | 896→**15万** |

- **QKV vs FFN**：同一车间的前后两道工序。注意力"搜集情报"（存关系/规律），FFN"分析情报"（存事实知识，接 3.6）。以"买了一台苹果"为例：注意力把"买/台"线索汇到"苹果"身上，FFN 再调用知识想出"苹果=手机公司"。
- **FFN vs lm_head**：FFN 每层都有、维度不变、管"理解"；lm_head 只在最后、896→15万、管"出结果"。
- **冷知识（权重共享）**：lm_head 常和进门的 embedding 表**共用同一套参数**——进门 token→向量（用表），出门 向量→词分数（用表的转置），省一半参数还更合理。

**地图位置**：把③（QKV+FFN，每层反复）和输出端（lm_head，末尾一次）的分工彻底串清。

## 补二.6 我问："那 QKV 和 FFN 都是固定的？"

**为什么问**：直觉它们像"固定的方法"，但又听说模型每次输出不同，想弄清到底哪固定哪不固定。（接 3.7 的老主题）

**解决的疑惑**：把"固定"拆成三层，别混：

```
① 流程/步骤       → 永远固定（QKV=Q点K→softmax→加权V；FFN=放大→激活→缩小）
② 参数(里面的数字) → 训练时在变，训练完冻结；用模型时不动
③ 每次算出的具体值 → 每个输入都不同（因为 = 输入 × 那套固定参数）
```

- **参数固定 ≠ 结果一样**：`本次Q/K/V = 本次输入 × 固定的Wq/Wk/Wv`。固定的是"机器/规则"，变的是"喂进去的料"（榨汁机比喻：机器固定，放苹果出苹果汁、放橙子出橙汁）。
- **各层各自固定、但彼此不同**：24 层=24 套独立参数，各学各的（车间1 可能学看语法、车间10 学看语义），学完各自冻结。

**地图位置**：回到贯穿全线的"固定流程 + 可学参数"母题（3.7），并补上"参数冻结 vs 每次结果随输入变"这层区分。

## 补二.7 延伸澄清（8/7 聊的，一并补记）

这几个是隔周之前聊的零散问题，一起记下：

**(a) 新模型都不用 temperature 了，还用 softmax 吗？**
- **方向纠正**：softmax 不"算 logits"；顺序是 `模型→logits→softmax→概率`，temperature 只是插在"÷T 再喂 softmax"这一步的**可选旋钮**。
- **结论**：temperature 可废、**softmax 拆不掉**。softmax 至少出现在 3 处：①每层 attention 算权重 ②输出端 logits→概率 ③训练算 loss。废 temperature 只是固定住那个旋钮，softmax 照用。
- **2026 现状（已联网核实）**：不是"新模型都不用"，是**推理模型**这一类砍了——Anthropic Opus 4.7/4.8/5、OpenAI o1/o3/gpt-5 设 temperature 直接 400；普通对话模型（GPT-4o、Qwen、LLaMA…）照旧开放。且官方措辞是"**temperature 固定在 1**"——是固定采样、**不是变贪心**。替代旋钮：effort（控推理深度）。

**(b) softmax 和激活函数(触发函数)什么区别？**
- "触发函数"="激活函数"，同一个词。softmax 算广义激活函数，但和 ReLU/GELU 那种**不同类**：
- **逐个 vs 整排**：ReLU/GELU 逐个数字独立处理；softmax 整排一起、要归一化成"和=1 的概率"（改一个数、全排都变）。
- **位置/作用**：ReLU/GELU 散布每层隐藏层、加非线性；softmax 只在 attention 和输出端、把分数变概率。
- softmax 是 sigmoid 的多类推广（二选一时退化成 sigmoid）。

**(c) Q/K/V 是所有模型通用的吗？GPT-5.5/Opus5 都用？**
- **核心通用**：几乎所有主流大模型都是 Transformer，Q/K/V 是其心脏；GPT/Opus/Gemini/LLaMA/Qwen/DeepSeek 全建在这上面。
- **实现一直在演进**（同是 QKV 但细节不同）：MHA→MQA→**GQA**（多头共享 K/V 省显存，主流）、**MLA**（DeepSeek，压缩 KV）、**FlashAttention**（更快，数学不变）、滑窗/稀疏注意力、**RoPE** 位置编码。
- **诚实边界**：GPT-5.5/Opus5 的精确内部（层数/头数/用 GQA 还是别的）**未公开**，只能确定"骨架仍是 Transformer + QKV"。
- **有没有不用注意力的路线**：有但属少数派——Mamba/状态空间模型(SSM)、线性注意力、混合架构(如 Jamba)。

## 补二.8 我把整个工作流程复述了一遍，并问："最后一层输出怎么了？softmax 在哪工作？"

**为什么问**：想自己把整条链从头串一遍，验证是否真懂，卡在两个环节。

**解决的疑惑**：我的复述基本全对（文字→分词→token→查 embedding 得向量→过 24 层、每层 wq/wk/wv+FFN），补上两个空：

- **空1（最后一层输出怎么了）**：最后一层出来**仍是一串向量**（每个 token 一个）；生成时取**最后一个位置**的向量 → 过 lm_head(896→15万) → logits。
- **空2（softmax 在哪工作）**：**两处，别只记末尾那处！**

```
① 每一层的注意力内部（很多次）：Q·K 的分 → softmax → 注意力权重(和=1)
   （24层 × 每层多头，被用了几百次）
② 最末尾（一次）：logits(15万分) → softmax → 概率 → 采样出下一个字
```

之前只知道②，其实①在每层的注意力里一直默默工作。

**地图位置**：把整条流水线（含 softmax 的两个位置）在"用户视角"下串成一张完整图，是对前三幕的总装配演练。

## 补二.9 我问："最后一层输出不也是一串向量吗？为什么最后一个向量经 lm_head 会有 15万 候选？不是只对应一个 token 吗？"

**为什么问**：发现"1 个向量 → 15万 分数"像自相矛盾。

**解决的疑惑**：

- **为什么只取最后一个位置**：每个位置的向量负责预测"它的下一个字"。前面那些字的下一个字**已知**（就是句子里的下一个），只有整句最后一个字之后是未知的 → 所以取最后一个位置。（训练时**所有位置一起用**，各预测各的下一字，故一次前向得到一整句预测，训练才高效。）
- **为什么 1 个向量 → 15万 分数**：lm_head 不是"把向量变成一个词"，而是**拿这个向量和词表里 15万 个词逐个点积打分**。15万 是"候选打分格"，**不是输出 15万 个词**。
- **最终**：1 向量 → 15万 logits → softmax → 选 1 个字。菜单比喻：点 1 道菜（最终 1 个 token），但要先看整本 15万 道菜的评分，再选出 1 道。

**地图位置**：讲清输出端"给全表打分→选一个"的机制，破除"1 个向量对 1 个 token"的直觉误解。

## 补二.10 我问："这样的话，token 查 embedding 为什么就是一个向量？"（抓到了进/出对称）

**为什么问**：既然出门"1 向量 → 15万 分数"，那进门为什么"1 token → 1 向量"，不对称？

**解决的疑惑**：其实用的是**同一张表**（15万 × 896，每个词占一行），只是**两个方向**：

```
进门(查embedding)：已知 token id(第几号词) → 直接取出那一行 → 1个向量   （按名取货）
出门(lm_head)   ：不知道下个词是谁 → 向量和全部15万行逐个点积 → 15万分数（全表比对）
```

**不对称的唯一原因**：进门**知道是谁**（分词已给出行号，照号取货），出门**要猜是谁**（只有向量、没行号，只能全表比一遍再选最高）。查字典比喻：知道要查"猫"就翻 1 页拿解释；只攥着一段意思、不知是哪个字，就得整本字典每页比一遍打分。

**地图位置**：把输入端(embedding)和输出端(lm_head)统一成"同一张表的正反两用"——至此从"文字进"到"文字出"两端彻底对称地理解了。

### 补幕二小结

前三幕是"拆"——沿流水线从右往左把每个零件抠开；这一幕是"合"——把注意力、FFN、embedding、softmax、参数拼回一个整体：**Transformer = 整句话顺序走过 N 个〔注意力收集上下文 + FFN 用知识消化 + 残差累加〕的车间，每层踩着上一层的成果把理解垒高一点，最后 lm_head 把成果翻译成下一个字的分数。** 而"固定流程 + 冻结参数 + 随输入而变的中间值"这三层区分，正是 3.7 那句"固定方法 + 学出来的参数 = 会技能的模型"的落地。

## 附：一句话概念卡（速查）

- **分词**：按频率查字典，token id 只是编号，无语义。
- **Token 表 / BPE**：训模型前用 BPE（谁常挨一起就合并）统计建出的固定表（Qwen2.5=15.1万）；常见词整词占1个、生僻词拆碎、终极兜底=256个字节token，覆盖一切输入。
- **表是私有的**：每个模型/大版本各建各的表；token id 不跨模型通用、权重不能混搭、同句话在不同模型里 token 数（费用）不同。
- **embedding**：训练学出的语义指纹，意思近则向量近。
- **点积/余弦**：a·b=|a||b|cosθ，衡量两向量方向+长度的匹配度。
- **attention**：固定流程(Q点K→softmax→加权V) + 可学 Wq/Wk/Wv；让词按需回看上下文；多头=多视角；KV缓存省重复计算；技能在矩阵取值里。
- **FFN**：每层固定的小网络，主要存事实知识。
- **logits**：模型输出的原始分数，本质是对数概率。
- **softmax**：用 exp 把 logits 还原成合法概率；exp 保证正数、保序、差→比。**两处上岗**：①每层注意力内部算权重（几百次）②最末尾把 logits 变概率（一次）。
- **temperature**：softmax 内的参数，等价 p^(1/T) 重整分布；调"胆量"不改排序；本质弥合"预测最优≠生成最优"；离了 softmax 的 exp 就失效。
- **采样**：贪心 ⊆ top-k ⊆ top-p；temperature 调赔率，top-k/p 删词。
- **参数量(0.5B)**：由维度/层数决定；知识分布式压缩存储，容量有限→冷门知识幻觉。
- **Transformer 架构**：整句话顺序走过 N 个"车间(Block)"，每车间=LayerNorm→注意力→残差；LayerNorm→FFN→残差；GPT/Opus/Qwen 都是 decoder-only。相比 RNN 胜在并行、长距离、可堆深。
- **层/深度**：一层=往前推理一步且踩上一层结果；复杂意思要绕多步→需多层；层内所有字并行、层间必须串行（层多则慢）；一次前向走完所有层只出一个字。
- **QKV vs FFN**：同一层前后两道工序——注意力"搜集情报(看别人、存关系)"，FFN"分析情报(看自己、存事实)"。
- **lm_head**：全程唯一、在最末尾，把最终向量 896→15万 翻成 logits；常与 embedding 表共享参数（进门 token→向量，出门 向量→词分数）。
- **进/出同表两用**：同一张表(15万×896)——进门查 embedding=已知词、按行号取1行(1向量)；出门 lm_head=不知词、和全表逐行点积(15万分数)。不对称只因进门知道是谁、出门要猜。生成时只取最后一个位置的向量去预测下一字。
- **固定 vs 可变**：流程永远固定；参数训练时学、训练完冻结；每次的 Q/K/V 与 FFN 输出随输入而变（固定机器+变化原料）。各层参数各自独立但都冻结。
- **softmax vs 激活函数**：激活函数(ReLU/GELU)逐个数字加非线性、遍布每层；softmax 整排归一化成概率、只在 attention 和输出端。
- **QKV 通用性**：所有主流大模型的核心；实现在演进（GQA 共享KV、MLA 压缩KV、FlashAttention、RoPE）；闭源模型精确内部未公开，骨架仍是它。
- **temperature 现状(2026)**：推理模型(Opus4.7+/o系列/gpt-5)砍了 temperature（固定在1，非贪心），普通对话模型照旧开放；softmax 拆不掉。
